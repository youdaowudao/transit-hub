# 用户最后使用记录

## 目标 / 需求快照

### 人类原本希望解决的目标

在 TransitHub 后台新增一个独立、简单的页面，按日期查看当前 workspace 中最近调用过 API 的 Sub2API 用户，并方便地复制用户名。

### 术语与数据口径

- 页面和代码中统一使用“最后使用时间”。
- 数据字段固定为 Sub2API `last_used_at`，表示用户最近一次调用 API 的时间。
- `last_active_at` 表示网页端活跃时间，本次不读取、不展示、不参与筛选。
- 不使用“活跃用户”“活跃时间”作为本页面的名称或字段说明。

### 成功标准

1. 后台导航中有独立的“用户最后使用”页面入口，不改造现有群发邮件页面。
2. 页面默认选中 Asia/Shanghai 的今天和昨天。
3. 日期支持多选：用户可通过日期输入添加多个日期，也可移除已选日期。
4. 结果按所选日期分组，日期和组内结果都按时间从新到旧排列。
5. 每个日期分组显示该日人数；每行只展示用户名和完整的最后使用时间。
6. 每一行的用户名旁都有独立复制按钮，点击后只复制该行用户名，并给出成功或失败反馈。
7. 页面只发起 GET 查询；不修改 TransitHub 或 Sub2API 任何数据。

### 筛选规则

- 日期匹配使用 Asia/Shanghai 自然日边界，按 `[00:00:00, 次日 00:00:00)` 判定，不直接对 UTC 字符串截断比较。
- 一个用户只出现一次，归入其当前 `last_used_at` 所属的日期。
- `last_used_at` 为空或不在所选日期内的用户不展示。
- 用户名为空的记录不展示；所有已展示行都必须有可用的用户名复制按钮。
- 时间固定显示为 `YYYY-MM-DD HH:mm:ss`，不用“刚刚”“2 小时前”等相对时间代替原始时间。

### 明确不做

- 不增加充值、余额修改、备注、批次执行或后台 worker。
- 不直接连接或查询 Sub2API 的 PostgreSQL 数据库。
- 不新增 TransitHub 数据库表、迁移、缓存或快照。
- 不展示邮箱、余额、角色、状态、注册时间或网页活跃时间。
- 不增加导出、全选、批量复制或其他群发功能。
- 不引入新的前端设计语言或页面重设计，直接复用现有管理后台布局、表格、按钮和日期输入样式。

### 固定约束与风险

- 数据来源是当前 workspace 已校验的 Sub2API 管理员会话，不能跨 workspace 读取。
- 当前 Sub2API 官方接口支持按 `last_used_at` 排序并返回该字段；若实际主站版本不支持，必须明确报错，不得回退成 `last_active_at`、`created_at` 或推测时间。
- 多日期查询需要按 `last_used_at` 倒序分页读取，直到越过已选最早日期或达到末页；不能只读第一页后就声称结果完整。
