# 实施方案

## 最小数据链路

1. 复用现有 `/api/mass-email/users` 只读用户列表接口和当前 workspace 的 Sub2API 管理员会话，不新建后端业务模块。
2. 在 Sub2API 用户查询排序白名单中增加 `last_used_at`，并继续由现有 URL 参数编码和管理员鉴权链路发起 GET 请求。
3. 在用户列表 DTO 中增加 `lastUsedAt`，直接返回已有解析结果，不增加本地持久化。
4. 保持现有群发邮件页的默认排序、筛选和发送行为不变；新页面只是该只读列表能力的新消费方。

## 新页面

1. 新增管理路由 `/admin/user-last-used`，并在现有侧边导航中增加“用户最后使用”入口。
2. 页面使用一个原生日期输入和“添加日期”按钮实现多选；已选日期以可移除的日期项显示，避免引入新日历组件。
3. 首次进入页面时，按 Asia/Shanghai 自动选中今天和昨天并立即查询。
4. 日期项去重后按从新到旧排列；至少保留一个已选日期，避免发起无边界查询。
5. 查询时使用 `page_size=100`、`sort_by=last_used_at`、`sort_order=desc`、`timezone=Asia/Shanghai`，不传 status、role 或 search 筛选。
6. 前端按页读取，遇到早于已选最早日期的非空 `lastUsedAt`、全部为空的排序尾部或最后一页时停止。
7. 将结果换算为 Asia/Shanghai 后按已选日期分组；页面展示日期标题、该日人数和用户表格。
8. 用户名为空的记录在分组前跳过，保证页面中每个展示用户都能直接复制用户名。

## 用户列表与复制

1. 表格固定为“用户名 / 最后使用时间”两列，复制按钮放在用户名右侧，不单独增加操作列。
2. 复制按钮使用现有 Lucide `Copy` / `Check` 图标和小型按钮样式，并提供 `title` 与 `aria-label`。
3. 点击后通过 `navigator.clipboard.writeText(username)` 复制准确用户名；成功时该行短暂显示 `Check`，失败时在页面显示“复制失败，请手动复制用户名”。
4. 复制状态按用户行记录，点击某一行不影响其他行。

## 错误与空状态

- 管理员会话缺失、过期或主站查询失败时，页面显示明确错误并保留重新查询入口。
- 所选日期没有结果时显示“所选日期暂无用户使用记录”。
- 返回记录缺少 `lastUsedAt` 时跳过该记录，不用其他时间字段填充。
- 返回记录缺少用户名时跳过该记录，不用邮箱或用户 ID 代替用户名。
- 请求期间显示单一加载状态，禁用重复查询，避免叠加多轮分页请求。

## 验证与收口

1. 后端定向测试覆盖 `last_used_at` 排序白名单、GET 查询参数、时间解析和 DTO 返回。
2. 前端定向测试覆盖默认两日、日期多选去重、上海日期分组、分页停止条件和逐行复制。
3. 运行相关 Go 包定向测试、前端 `typecheck` / 定向测试 / 构建和 `git diff --check`，不运行全仓测试。
4. 代码修改完成后按项目固定规则重启 `5444` 前端与 `5555` 后端，确认两端唯一实例、健康检查和数据库连接目标不变。
5. 通过真实页面核对默认两日、多日期分组、完整时间和每行复制反馈。
6. 实施时将代码内置版本和提交标题预留为 `V2.1.19`；未获得用户提交许可前不执行提交。
