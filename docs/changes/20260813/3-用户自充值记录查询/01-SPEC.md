# 用户自充值记录查询

## 目标

在现有“用户最后使用”页面内增加“充值记录”查询，汇总所有通过兑换码自行充值余额的用户，并排除管理员充值。

## 成功标准

- 页面仍使用 `/admin/user-last-used`，以同页模式切换展示最后使用记录和充值记录，不新增菜单、路由或页面。
- 数据只读取 Sub2API `redeem_codes` 中 `type=balance`、`status=used`、`value>0` 的记录；`admin_balance` 不计入。
- 站内或站外购买的兑换码在实际兑换后均按兑换记录统计。
- 按 `used_by` 聚合，展示真实邮箱、兑换次数、累计充值余额和最近兑换时间；不展示用户名。
- 全量分页只在完整成功后返回结果；请求支持取消、超时和响应体上限，异常时不返回部分数据。

## 明确不做

- 不统计支付订单或未兑换的兑换码。
- 不创建本地业务表、缓存、后台轮询或同步任务。
- 不修改 Sub2API 数据，不改变现有用户最后使用查询的数据来源。

## 固定约束

- 后端只读调用 Sub2API 管理端兑换码列表接口，固定按兑换时间倒序分页。
- 邮箱取兑换记录关联用户的 `email` 字段；缺少用户或邮箱时整次查询报错，不静默漏记。
- 分页总数在查询期间变化时整次查询报错，避免把不一致的分页结果当作成功结果。
