# 首页分组利润核算闭合修复

状态：待开发。

## 目标 / 需求快照

### 人类原本希望解决的目标

修复首页“分组贡献”中的营收、成本和利润核算：有正营收的分组必须正常显示营收；只有已完整闭合核算的分组才显示利润；真实完成核算后的负利润仍应正常显示，不能用归零或钳制掩盖问题。

### 已确认事实

- 这是后端归因链路错误，不是图表渲染问题。
- 当前实现将按账号加分组查询得到的营收同时用于分组展示和连接归因；存在真实接入时又禁止分组总营收回退，导致成员变化、账号级查询失败或返回零时，分组的正营收可能丢失。
- 当前连接循环会把“分组总营收减当前单条连接成本”写入整个分组；同一分组多条连接时，成本和利润随最后一次遍历覆盖。Go map 遍历顺序不稳定，结果可能随运行改变。
- 当前多分组连接会从 `expectedConnections` 的核算流程中静默跳过，未核算数与问题数不能闭合。
- 当前全局质量为 `partial` 时仍允许返回分组利润，前端仅检查利润字段是否存在，因此可能展示错误金额。
- 本地缓存的业务日期已更新；本地有同组多真实接入可复现核心拓扑。服务器截图对应的历史连接和流水已不在本地，不能用本地金额复算截图金额。

### 核算合同

1. 营收分为两条独立数据链，均使用同一上海业务日：
   - `displayRevenueByGroup`：从 Sub2API 分组汇总一次读取，以稳定的 `group_id` 为键；是营收图、分组 `todayRevenue` 和分组正式利润中的营收权威值。
   - `connectionRevenue`：按 `account_id + group_id` 查询；只用于验证真实接入闭包，以及计算单条连接的利润。
2. 对一个分组，正式成本等于该分组内全部 `exact` 真实接入 Key 的成本之和；正式利润等于该分组的权威分组营收减正式成本。不得在单条连接循环中写入或覆盖分组利润。
3. 单条连接利润等于该连接的 `connectionRevenue` 减该连接 Key 成本；不得使用分组总营收替代连接营收。
4. 每一条进入 `expected` 的真实接入都必须有且只有一个终态：`exact`、`failed` 或 `unallocatable`。`expected = resolved + failed + unallocatable` 必须成立；每条非 `exact` 连接都必须至少产生一条带该 `connectionId` 的问题。
5. `exact` 需要同时满足：单一且有效的分组关系、无重复 Key 或重复账号绑定、当前主站成员关系一致、连接级营收查询成功、Key 成本存在（真实零成本也算存在），以及同一分组的连接级营收之和与权威分组营收在统一固定金额精度内一致。
6. 一个分组只有当其全部应核算连接均为 `exact`，且通过上述营收对账时，才可返回非空 `todayCost` 和 `todayProfit`。受影响分组仍保留权威 `todayRevenue`，但成本和利润必须为 `null`。
7. 全局为 `partial` 时，其他已完整闭合的分组仍可展示正式利润；`totalProfit` 和 `totalCost` 只在全部应核算连接闭合时返回，否则为 `null`。
8. `unbound_upstream_cost` 继续作为未绑定成本诊断，不分摊、不混入任何正式分组成本或利润，也不伪造连接终态。

### 成功标准

1. 分组营收始终来自稳定 `group_id` 的 Sub2API 分组汇总，不能被连接成员变化、连接级查询失败或零值覆盖或隐藏。
2. 同分组多接入的成本精确累加一次，分组和连接利润不再依赖遍历顺序。
3. 任一连接不完整、成员已变化、营收不一致、重复绑定或多分组时，受影响分组不再输出错误的成本或利润。
4. 质量计数与问题记录按连接闭合；多分组、重复绑定、Key 缺失和查询失败均能定位到具体连接。
5. 前端仅绘制 `status === exact` 且 `todayProfit != null` 的利润柱；营收模式继续显示全部可读分组营收。
6. 已完整核算出的负利润正常展示；不能以负数保护掩盖真实亏损。

### 明确不做

- 不自动修改、同步或纠正 `real_connections`。
- 不新增 `membershipUnknown`，不将真实成员关系变化隐藏为未知。
- 不把 NewAPI 当主站，也不增加主站 NewAPI 核算逻辑。
- 不只做同组成本累加，不允许一条失败、一条成功时把分组误标为 `exact`。
- 不改写首页总营收、总成本缓存链路；本变更只修复分组贡献接口及其前端展示边界。
- 不把 `unbound_upstream_cost` 分摊给任意分组，不用猜测关系补齐缺失成本或营收。
- 不做负数归零、截断或其他数值美化。

### 固定约束与风险

- 主站唯一按 Sub2API 链路核算；日期固定为 Asia/Shanghai 业务日。
- 现有主站账号与连接记录中的账号/分组不一致是可能真实发生的状态，必须如实标为问题，不得自行修复数据。
- 金额对账必须使用单一、命名的固定金额精度常量；实现、测试和接口语义使用同一精度，不得散落临时浮点比较。
- 本变更会让此前错误展示的分组利润消失或改变，这是口径修复，不代表新增成本。
- 旧的 `20260812/1-首页分组利润核算误报修复.md` 只保留为历史分析，尤其不得恢复其中的 `membershipUnknown` 或“绑定分组禁止展示营收回退”处理。
