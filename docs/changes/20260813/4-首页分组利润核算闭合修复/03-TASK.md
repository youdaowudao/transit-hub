# 高风险任务拆分

状态：待开发。任务须按顺序完成；任何未解决的对账问题都不得以展示利润收口。

## 1. 固化分组汇总契约

- 为日期正确的 Sub2API 分组汇总结果保留 `group_id`、分组名称和金额。
- 为正常响应、缺少 `group_id`、缺少金额、日期参数和管理员鉴权补定向测试。
- 验收：同名分组不能合并；展示营收只按 ID 写入。

## 2. 重建连接终态输入

- 构造启用站点 active 连接的 expected 集合，不再在中间循环静默 `continue`。
- 为每个 expected 连接创建可追踪的终态和问题归属。
- 保留 inactive、禁用站点和未绑定成本的诊断边界，但不让它们污染 expected 闭合。
- 验收：每次运行均满足 `expected = resolved + failed + unallocatable`，每条非精确连接均可从问题列表按 `connectionId` 找到原因。

## 3. 分离营收并核对成员关系

- 先读取权威分组营收，再独立读取连接级营收；两者不得写入同一映射。
- 真实成员变化直接标为连接失败；不创建未知成员状态，不自动同步连接数据。
- 按账号加分组查询失败时，将所有受影响连接标为失败，但对应分组仍显示权威营收。
- 验收：成员变化、连接级营收失败和真实零营收都不会抹掉分组营收。

## 4. 改为后置聚合

- 在所有连接终态完成后，聚合 exact 连接的连接营收和 Key 成本。
- 使用共享固定金额精度执行“连接营收和 = 分组权威营收”对账；不一致时为受影响分组写明问题并清空正式成本、利润。
- 同组成本、分组利润和连接利润各自按其合同计算，移除任何连接循环覆盖分组结果的代码。
- 验收：交换输入顺序或重复运行不会改变金额、状态、计数或问题归属。

## 5. 收紧接口和图表展示

- 精确分组可在全局 partial 中保留正式成本、利润；非精确分组的成本、利润必须为 `null`。
- 全局总成本、总利润只在全局闭合时返回；全局 partial 不得返回部分总计。
- 前端利润柱显式检查分组精确状态和非空利润；营收柱不受影响。
- 验收：部分连接失败时，仅无关的精确分组可画利润柱；受影响分组只保留营收。
