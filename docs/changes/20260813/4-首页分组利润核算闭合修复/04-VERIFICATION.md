## 必须通过的定向测试

| 场景 | 必须证明的结果 |
| --- | --- |
| 同组两条及以上连接 | 分组成本为全部 Key 成本之和；分组利润只计算一次；交换输入顺序结果相同。 |
| 一条 exact、一条失败 | 分组保留权威营收，`todayCost`、`todayProfit` 均为 `null`；全局不返回总成本、总利润。 |
| 一条 exact、一条 unallocatable | 计数和问题按连接闭合；分组不显示正式利润。 |
| 多分组连接 | 连接被标为 `unallocatable`，带 `connectionId` 问题；不允许静默遗漏。 |
| 重复 Key / 重复账号 | 每条受影响连接都为 `unallocatable`，不分摊成本或营收。 |
| 主站成员关系变化 | 连接为 `failed`，不自动修改真实连接；分组权威营收仍显示。 |
| 连接级营收查询失败 | 受影响连接逐条 `failed`，分组营收仍显示，分组不显示成本或利润。 |
| 分组营收与连接营收不一致 | 记录可定位的对账问题，分组不显示成本或利润。 |
| 真实零成本 | Key 成本零值仍为已读取成本，可在其他条件满足时得到精确利润。 |
| 真实负利润 | 全部闭合后仍按实际负数返回并在利润图展示。 |
| 未绑定上游成本 | 仅显示诊断，不进入分组成本、分组利润或连接计数。 |
| 全局 partial | 精确分组可展示利润；非精确分组不展示；总利润和前三分组利润占比不可用。 |

## 协议与界面检查

- Sub2API 分组汇总解析测试覆盖稳定 `group_id`、指定业务日和金额字段；不以分组名称归集。
- Go 定向测试覆盖归因顺序稳定、质量闭合、成员变化、查询失败、对账不一致和零成本。
- 前端定向测试或可重复页面检查覆盖利润模式的 `exact` 二次筛选、营收模式完整展示和总利润不可用状态。
- 运行前端类型检查、前端构建和 `git diff --check`。
