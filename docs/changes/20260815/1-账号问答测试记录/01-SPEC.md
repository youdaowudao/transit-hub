# 账号问答测试记录需求

当前版本基线：`V2.2.5`

## 目标 / 需求快照

### 人类原本希望解决的目标

当前闪电弹窗只能做正式探活和一次性测试，一次性测试只判断请求成败，不保留模型的回答。需要在同一个弹窗内增加第三个“问答测试”模式，让用户选择预设问题向当前账号发起一次独立请求，保存回答，并手工标记哪次回答出错。

这不是新的探活体系。本次只复用现有一次性测试的账号定位、模型发现、服务端凭据解析和 OpenAI 兼容请求能力，补上可选问题、回答提取、记录和人工错误标记。

### 成功标准

1. 分组健康的闪电弹窗从两个模式增加为三个：正式探活、一次性测试、问答测试。
2. 设置页增加“测试问题”管理入口，可新增、编辑、启停、删除问题并设置默认问题。
3. 问答测试沿用现有模型选择；可勾选一个或多个问题，有默认问题时每次打开自动勾选该问题。
4. 每个“模型 × 问题”只发起一次独立请求，不携带上一次对话，不自动重试。
5. 请求完成后只保存提取出的回答正文和必要的归属、状态字段，不保存原始 Body、原始 JSON、响应头或完整 HTTP 报文。
6. 同一账号无论出现在多少个主站分组或其他业务视图中，始终只有一份以稳定 `targetId` 为归属的问答记录。
7. 记录页顶部显示已完成的总数、正常数和错误数；历史列表按时间倒序，最新记录在最前，每页固定显示 20 条。
8. 成功返回的回答默认为淡绿色正常状态。用户点击记录旁的错号按钮后，该记录变为淡红色错误状态；再次点击恢复正常。
9. 错误标记点击后立即自动保存，不设置额外“保存”按钮。关闭后重新打开，颜色、错误计数和记录状态必须与数据库一致。
10. 点击开始后，前端不等待全部问答完成。弹窗保持打开时实时展示“已完成数 / 总数”、当前模型、当前问题和最新回答；全部完成后立即展示最终结果，不要求重新打开。
11. 用户可关闭弹窗或切换页面，已创建的问答仍由后端继续执行；重新打开时读取服务端已保存的最新状态和结果。进行中可点击“终止本次问答”，主动停止当前批次。

## 界面合同

### 闪电弹窗

- 现有闪电图标和弹窗保留，不在分组健康主表增加新的常驻按钮。
- 现有小眼睛继续查看健康事件，本次不改小眼睛。
- 问答测试作为闪电弹窗第三个模式，不新建独立页面，也不放大现有弹窗。内容在现有弹窗内部滚动。
- 问题和模型采用多选；未选中任何问题或模型时不允许开始。
- 弹窗内容从上到下固定为：模型与问题选择区、当前批次进度与最新回答、历史记录。选择区和当前回答优先显示在首屏，历史记录放在下方；首屏能露出少量历史即可，更多历史通过向下滚动查看。
- 选择区分别展示模型复选项和问题复选项，并显示“已选模型数 × 已选问题数 = 本次请求数”。进行中锁定本次选择，完成或终止后才允许调整并再次开始。
- 当前批次区显示“已提交，共 N 项”“已完成 X/N”“正在测试：模型名称 × 问题名称”。每个组合显示等待中、进行中、已完成、失败或已终止；最新完成的回答在下一次状态刷新时显示，通常不超过 2 秒。
- 列表默认只展示问题名称、模型、时间、回答摘要和状态；点击记录展开完整问题和完整回答。
- 历史记录每页显示 20 条，使用页码翻页；顶部统计始终针对当前账号的全部已完成记录，不是当前页小计。
- 成功回答的人工错误标记只修改判定状态，不允许编辑或覆盖原回答正文。
- 请求本身失败时直接显示淡红色错误记录并计入错误数，不伪造回答内容。

### 顶部统计

顶部统计只计算已完成记录：

- 总数：已完成的全部请求数。
- 正常：成功返回且未被用户标记为错误的数量。
- 错误：请求失败或被用户标记为错误的数量。

正常数与错误数之和必须等于总数。仍在执行的记录可在列表中显示“进行中”，但完成前不计入这三个数字。

用户主动终止后，正在执行和尚未执行的组合显示为中性的“已终止”，不计入总数、正常数或错误数；终止前已经完成的记录保持原统计结果。单项达到 10 分钟超时则属于请求失败，计入错误数。

## 数据归属与保存边界

### 问题库

问题库跟随当前 TransitHub 用户，作为设置页的唯一可写入口；当前只有一个 workspace，本阶段不增加多 workspace 的额外配置或界面。当问题库中还没有问题时，第一个新增问题自动成为默认问题；设置新默认问题时取消旧默认。默认问题被停用或删除时清空默认状态，不自动指定另一个问题。系统不自行创建未经用户确认的测试提示词。

### 问答记录

问答记录跟随当前用户和稳定 `targetId`。同一次选中多个问题或模型时，各请求仍分别形成记录，只使用一个 `batchId` 表示它们来自同一次点击。

只保存以下内容：

- `targetId`、模型名称和 `batchId`。
- 问题 ID、问题名称快照和问题全文快照。
- 提取后的回答正文。
- 执行状态、安全错误类型、创建时间和完成时间。
- 用户是否标记为错误。

明确不保存：

- API Key、`Authorization`、Cookie 或其他凭据。
- 原始请求头、原始响应头和完整 HTTP 报文。
- 原始响应 Body、原始 JSON 或解析前的错误页。
- 原始响应 Body 的截断片段、只替换凭据后的脱敏片段，或现有 `ProbeOutcome.Detail` 中的上游原文。
- Usage、协议指纹、行为评分、真实性结论或 Codex 分析结果。

问题名称最多 100 个字符，问题正文最多 4000 个字符。问答请求不额外发送 `max_tokens`，不套用轻量探活的 10 秒超时；每个“模型 × 问题”请求单独设置 10 分钟上限。单项超时记为失败并继续下一项，不自动重试。历史列表每页读取 20 条，本阶段不做自动过期和自动删除。

## 现有能力复用

- 复用现有 `targetId` 归属验证，前端不传入 Base URL 或 Key。
- 复用一次性测试的服务端凭据解析、模型发现、OpenAI 兼容 `/v1/chat/completions` 端点、鉴权方式、底层 JSON 请求能力和响应大小保护。
- 问答测试使用自己的记录表和接口，但不新建第二套上游协议客户端。
- 现有 `RealProbeRunner` 和 `buildProbeRequest` 固定包含 10 秒超时和 `max_tokens`，问答不能原样调用；只在现有客户端边界内增加省略 `max_tokens`、使用 10 分钟问答超时的载荷构造。
- 问答测试始终保持一次性隔离语义，不读写 `connection_health_states`、`connection_health_events`、Priority、`schedulable`、探活预算或远端动作，不占用正式健康探活的并发配额。
- 成功响应只提取 assistant 回答正文；原始 Body 解析完成后立即丢弃。请求失败只保存系统内部的安全错误类型，不保存上游原文及其脱敏片段。

## 明确不做

- 不引入 Codex、AI 自动分析、自动评分或自动判定模型真假。
- 不抓包，不保存协议证据，不检查 identity 之外的隐藏指令或上游路由特征。
- 不修改正式探活和现有一次性测试的原有行为。
- 不修改小眼睛事件弹窗，不在分组健康主表增加新列或新按钮。
- 本阶段不在分组倍率、调价映射和上游站点页面额外展示统计或复制记录界面；记录已按账号 `targetId` 保存，后续需要时可以从其他入口读取同一份数据。
- 不建立多轮对话、测试套件、协议评估、数据导出或全局排行榜。

## 固定约束与风险

- 问答测试只复用现有请求构造、凭据和安全边界，不复用轻量探活的 `max_tokens=1` 和 10 秒超时。问答不额外设置生成 token 上限，每个“模型 × 问题”最多等待 10 分钟。
- 同一次多问题、多模型按请求组合顺序执行，本阶段不为加速额外并发打满上游。
- 同一用户的同一 `targetId` 同时只允许一个问答批次进行，重复点击或其他页面再次发起时直接返回“已有问答进行中”，避免后台任务叠加。
- 发起后与弹窗和 HTTP 请求的生命周期解耦。服务重启会中断当时尚未完成的内存执行，重启后这些记录统一收口为失败，不自动重试。
- 用户点击“终止本次问答”时，只终止当前批次；已完成回答保留，正在执行和等待中的记录收口为“已终止”，释放该账号的运行占用后可重新开始。
- 错误标记是用户对回答的人工判断，不是系统自动证明模型真假。
