# 账号问答测试记录实施计划

## 1. 数据库记录

1. 使用实施时下一个可用的 PostgreSQL 迁移编号新增问题表和问答记录表，并在 `connection_health.Repository.EnsureSchema` 中保持同样的幂等建表结构。不把运行数据写入项目目录或 JSON 文件。
2. 问题表保存当前用户、问题名称、问题正文、启用状态、默认状态和时间字段。问题名称最多 100 个字符，问题正文最多 4000 个字符。
3. 同一用户同时最多一个已启用默认问题；问题库中的第一个问题自动设为默认，更换默认时在同一事务中取消旧默认。停用或删除当前默认问题时清空默认状态，不自动选择替代问题。
4. 记录表保存当前用户、`targetId`、`batchId`、模型、问题 ID、问题名称快照、问题全文快照、回答正文、执行状态、安全错误类型、人工错误标记和时间字段。问题被删除时不得级联删除历史记录。
5. 记录执行状态固定为 `pending`、`running`、`succeeded`、`failed`、`cancelled`。前端分别显示等待中、进行中、已完成、失败和已终止；只有 `succeeded`、`failed` 计入顶部统计。
6. 不新增原始 Body、响应头、Usage、请求参数快照或协议分析字段；不保存原始 Body 的截断或脱敏片段。
7. 建立“用户 + `targetId` + 创建时间倒序 + 记录 ID 倒序”索引。历史查询固定每页 20 条，后端返回当前页、总页数和全部已完成记录的统计，不一次返回全部长文本。

## 2. 测试问题管理

1. 在现有设置页增加独立的“测试问题”标签，不将问题配置混入通知模板或健康策略。
2. 增加问题列表、新增、编辑、启停、删除和设为默认接口；所有接口都按当前登录用户隔离。
3. 问题名称和正文必须非空，并按 100/4000 字符上限校验；前端展示明确的校验失败信息。
4. 删除或编辑问题不更改历史记录；发起时将问题名称和全文写入记录快照，历史显示只读快照，不通过关联问题表重新取值。
5. 发起问答时，服务端重新校验问题属于当前用户且仍为启用状态，不信任前端缓存的问题内容或状态。

## 3. 问答请求复用

1. 在 `connection_health` 现有边界内增加隔离的问答测试方法。复用现有一次性测试的目标解析、模型发现、凭据解析、OpenAI 兼容端点、鉴权方式、底层 JSON 请求能力和响应大小保护，只新增问题内容、回答提取和记录逻辑；不复制第二套上游协议客户端。
2. 服务端只接收 `targetId`、模型列表和问题 ID 列表。目标归属、问题内容、Base URL 和 Key 都由服务端重新解析，不信任前端传入的目标细节或提示词全文。
3. 同一个后台批次中只解析一次账号凭据，然后按“已选模型 × 已选问题”顺序执行，每个组合只执行一次。对重复的模型名或问题 ID 先去重，防止同一组合被重复请求。
4. 请求继续使用 OpenAI 兼容 `/v1/chat/completions`、现有凭据头和非流式返回；不因模型声称为 Anthropic、Kiro 或其他渠道而切换官方协议。
5. 现有 `RealProbeRunner` 和 `buildProbeRequest` 固定包含 `max_tokens` 与 10 秒超时，问答方法不得原样调用。问答在同一 OpenAI 兼容客户端边界内使用独立载荷构造，不发送 `max_tokens`；每个“模型 × 问题”使用独立的 10 分钟请求上下文。单项超时记为 `failed` 并继续下一项，不自动重试。
6. 成功响应只解析 `choices[0].message.content` 的可展示文本，解析不到回答正文时记为请求失败，不为第一版扩展其他协议结构。
7. 成功记录只写入提取后的回答正文。失败记录只写入系统内部的安全错误类型，不写入 `ProbeOutcome.Detail`、原始 Body、原始 JSON、错误页或它们的截断/脱敏片段；解析完成后立即丢弃原始 Body。
8. 问答方法不调用现有 `ManualProbeTarget`、`RealProbeRunner`、正式 `ProbeTarget`、`probeTargetOnce` 或正式批次收口逻辑，只复用它们下层的安全能力；不写健康状态、事件、Priority、`schedulable`、探活预算或远端动作，不占用正式健康探活的并发配额或目标租约。

## 4. 后台执行与状态

1. 发起问答时，服务端在同一事务中校验目标和问题，为每个“模型 × 问题”组合写入问题快照并创建 `pending` 记录。
2. 记录创建成功后，发起接口立即返回 `batchId` 和已创建记录；不等待上游回答完成。
3. 当前后端进程使用与 HTTP 请求无关的服务生命周期上下文，在内存中按组合顺序执行该批次。开始单个组合前将状态改为 `running`，完成后改为 `succeeded` 或 `failed`。
4. 同一用户的同一 `targetId` 同时只允许一个活动批次。服务端以该归属做原子校验，已有 `pending/running` 时拒绝再次发起；前端同步禁用开始按钮并显示当前批次。
5. 增加终止当前批次接口。终止操作只接收当前 `targetId` 和 `batchId`，校验用户归属后取消当前请求；已完成记录保持不变，`running/pending` 记录统一改为 `cancelled`，不创建回答正文，也不计入顶部统计。重复终止必须保持幂等。
6. 关闭弹窗、前端请求结束或切换页面只停止前端刷新，不取消后端已创建的批次；只有用户明确点击“终止本次问答”、单项达到 10 分钟或服务关闭时才取消对应请求。
7. `connection_health.Service` 增加独立生命周期 `context/cancel`、活动批次表和 `WaitGroup`。批次结束、失败或终止时必须通过 `defer` 删除活动占用、取消单项计时器并退出协程；服务关闭时先取消全部问答，再等待协程回收，并接入现有 `Server.Shutdown`。
8. 问答请求复用一个共享 HTTP Client；每次响应都必须关闭 Body，解析后立即丢弃原始字节。不得为每个问题永久创建 Client、Transport、定时器或未回收协程。
9. 本阶段不建立独立持久队列、新 worker 服务、自动重试或并发执行器。实际执行只是当前后端进程内的一个顺序后台任务，也不占用正式健康探活配额。
10. 服务启动时，将数据库中上一个进程遗留的 `pending` 和 `running` 记录统一改为 `failed`，保存固定的安全中断类型，不自动补发。

## 5. 查询、统计与人工标记

1. 历史接口以“当前用户 + `targetId`”查询，固定按 `created_at DESC, id DESC` 返回，每页 20 条。
2. 历史响应同时返回当前页、总页数、已完成总数、正常数和错误数。三个统计值针对当前 `targetId` 的全部已完成记录，不是当前页小计。
3. 人工标记接口只接收布尔状态，并同时校验记录属于当前用户和当前 `targetId`。
4. 成功记录可在正常与人工错误之间切换；请求失败记录固定为错误，不允许人工改成正常。
5. `cancelled` 记录在历史中使用中性“已终止”状态，不提供正常/错误切换，也不进入已完成总数、正常数或错误数。

## 6. 前端界面

1. 在现有 `ManualOneTimeProbeDialog` 的正式探活和一次性测试之后增加第三个“问答测试”模式，保留弹窗原有尺寸、头部、关闭方式和单一内容滚动区，不扩大弹窗。
2. 问答模式的模型列表使用现有一次性测试的模型发现结果，不使用只属于正式健康策略的 `formalModels`，不要求账号已分配健康策略。在模型多选下增加问题多选区；有默认问题时初始只勾选默认问题，用户仍可勾选或取消任意问题。
3. 弹窗内容顺序固定为“模型与问题选择区 → 当前批次与最新回答 → 历史记录”。前两部分优先占据首屏，历史放在下方；首屏只需露出少量历史，用户通过弹窗内部向下滚动查看更多记录。
4. 模型继续使用现有复选卡片样式；问题使用紧凑复选列表，展示问题名称、默认标记和正文摘要。选择区显示“模型 M 个 × 问题 Q 个 = 共 N 次请求”，不绘制完整组合矩阵。
5. 没有启用问题时直接提示前往设置添加。批次进行中时锁定选择区并禁用再次开始，完成或终止后恢复选择。
6. 当前批次区在发起接口返回后立即插入全部组合，显示“已提交 N 项”“已完成 X/N”和当前“模型 × 问题”。等待中使用普通状态，进行中使用加载图标；单项完成后在下一次状态刷新时显示最新回答，通常不超过 2 秒。
7. 弹窗打开且批次进行中时，每 2 秒读取一次服务端状态。每次读取都更新组合状态和最新回答；全部进入终态后立即做最后一次刷新、显示完成提示并停止轮询，不要求用户重开弹窗。
8. 当前批次区在进行中显示“终止本次问答”按钮。点击后立即调用终止接口，成功后将未完成组合显示为中性的“已终止”；关闭弹窗本身不得触发终止。
9. 问答区顶部使用紧凑统计显示已完成总数、正常数和错误数，不在分组健康主表增加统计列。
10. 历史记录每项同时显示问题名称、模型、时间、回答摘要和状态，并以记录 ID 作为前端唯一键；成功且未标错记录使用淡绿色和对勾，请求失败或人工标错记录使用淡红色和错号，已终止记录使用中性样式。
11. 成功记录右侧提供图标按钮切换错误标记，按钮带工具提示。点击后立即调用保存接口并更新顶部统计；保存失败时恢复原状态并显示错误。
12. 回答列表固定每页 20 条，使用页码翻页。记录默认显示摘要，点击展开完整问题和回答，长文本不得撑开弹窗或遮挡操作。新发起一批问答后回到第 1 页。
13. 关闭弹窗、切换模式或组件卸载时立即清除前端轮询定时器和本次状态请求；这里只停止前端刷新，不取消后端批次。

## 7. 定向验证

1. PostgreSQL 迁移与 repository 测试覆盖：迁移与 `EnsureSchema` 幂等一致、用户隔离、唯一默认问题、停用/删除默认问题、编辑/删除后历史快照不变、五种状态转换、已终止记录不进入统计、每页 20 条倒序分页、全量统计口径和标记更新。
2. `connection_health` 定向测试覆盖：稳定 `targetId` 跨分组归属、一次性模型发现、无正式健康策略时仍可问答、凭据不外泄、问题 ID 服务端解析、回答正文提取、多组合去重后单次顺序执行和请求失败。
3. 定向测试必须证明问答请求不发送 `max_tokens`、不受轻量探活 10 秒超时限制，但每个组合有独立 10 分钟上限；单项超时记为失败并继续下一项，前端关闭或请求返回后后台仍可完成记录。
4. 隔离测试必须证明不写健康状态、事件、Priority、`schedulable`、探活预算或远端动作，不占用正式健康探活的并发配额和目标租约。
5. 安全测试使用带唯一标记的上游错误 JSON 和错误页，反查数据库不存在原始 Body、JSON、截断/脱敏片段、Usage 或凭据。
6. 后台生命周期测试覆盖：同一账号重复发起被拒绝、终止接口幂等、完成/失败/超时/终止后活动占用和计时器释放、响应 Body 关闭、协程退出，以及服务关闭时取消并等待问答任务；服务重启后遗留的 `pending/running` 记录收口为失败且不重试。
7. 前端定向测试覆盖：第三模式、模型发现结果、默认问题、多问题提交、组合总数、当前进度、每 2 秒刷新、完成后立即展示、终止按钮、关闭后轮询清理、每页 20 条倒序列表、绿/红/中性状态、标记自动保存、统计即时变化和失败回滚。
8. 运行 `go test ./internal/modules/connection_health -count=1`、新增 repository 定向测试、对应前端行为测试、`npm run typecheck`、`npm run build` 和 `git diff --check`，不运行全仓测试。
9. 浏览器验收覆盖：保持原弹窗尺寸和内部滚动、选择区与当前回答优先显示、实时进度和完成回填、点击开始后立即关闭弹窗、后台继续执行并落库、重新打开后读取结果、主动终止、每页 20 条翻页、最新在前、标错后自动保存及统计更新。
10. 实现阶段按项目固定规则更新版本，并在修改完成后重启固定 `5444/5555` 服务，核对数据库身份、工作区和关键数据数量未异常变化。

## 8. 风险与回滚

- 风险：选中的模型和问题数量相乘会增加外部请求数，且单次回答最多等待 10 分钟。本阶段只按组合顺序执行，同一账号只允许一个活动批次，不额外并发，不自动重试。
- 风险：长期记录会增加数据库文本量。本次只保存回答正文，并使用分页读取，不保存原始 Body 和网络报文。
- 风险：用户把“未标错”理解为系统已证明正确。界面只展示正常/错误人工记录，不生成真实性结论。
- 风险：后台问答任务只存在当前后端进程内存中，进程重启时未完成的请求会中断并记为失败，不会自动补发；服务正常关闭时必须先取消并等待这些任务释放。
- 回滚：回退前后端入口和问答执行代码后，现有两种探活模式恢复原样；新表保留但不再读写，不影响现有健康状态和调度数据。
