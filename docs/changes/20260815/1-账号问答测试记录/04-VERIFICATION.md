# 账号问答测试记录验证记录

状态：实现与定向验证完成，提交版本 `V2.2.7`。

## 验证范围

- 问题库的新增、编辑、启停、删除、第一条自动默认、唯一默认，以及停用/删除默认问题后清空默认状态。
- 问题名称 100 字符和问题正文 4000 字符的边界校验，以及编辑或删除问题后历史快照保持不变。
- 问答测试复用现有一次性测试的稳定 `targetId`、模型发现、凭据解析、OpenAI 兼容端点、鉴权方式和底层 JSON 请求能力；不原样调用带 10 秒超时和 `max_tokens` 的现有探活执行器，也不要求目标已分配正式健康策略。
- 一个或多个问题与一个或多个模型去重后的单次顺序组合执行；同一账号同时只允许一个活动批次，无并发加速和自动重试。
- 问答请求不发送 `max_tokens`，不复用轻量探活的 10 秒超时；每个“模型 × 问题”最多等待 10 分钟，单项超时记为错误并继续下一项。
- 点击开始后接口立即返回；弹窗打开时每 2 秒更新进度和最新回答，全部完成后立即展示最终结果。关闭弹窗或切换页面不取消后台执行，重新打开后继续读取服务端状态。
- “终止本次问答”只终止当前批次，已完成回答保留，未完成组合显示为中性的“已终止”且不进入顶部统计；终止后运行占用立即释放。
- 服务重启后，上一进程遗留的 `pending/running` 记录统一收口为失败，且不自动重试。
- 只保存回答正文和安全错误类型，不保存原始 Body、原始 JSON、响应头、完整报文、Usage、凭据或任何原始响应的截断/脱敏片段。
- 问答执行不修改健康状态、事件、Priority、`schedulable`、探活预算或远端动作，不占用正式健康探活的并发配额和目标租约。
- 账号记录按稳定 `targetId` 统一归属，同一账号出现在多个分组时仍只读写同一份历史。
- 历史固定按最新优先每页 20 条翻页，关闭后重新打开仍可读取。
- 顶部累计统计和按东八区计算的今日统计口径，以及绿色正常/红色错误的人工标记和自动保存。
- 闪电弹窗保持现有尺寸和内部滚动，选择区、当前进度与最新回答优先显示，历史记录排在下方；不改小眼睛和其他页面。
- 后台批次完成、失败、超时、主动终止或服务关闭后，响应 Body、计时器、活动占用和协程均被释放；弹窗关闭或完成后前端轮询也被清除。

## 实际结果

### 实现结果

- 本地版本已更新为 `V2.2.7`。新增 `000025_connection_health_question_answers.sql`，建立测试问题表和问答记录表；`Repository.EnsureSchema` 保持相同幂等结构。
- 问题管理按当前用户隔离，支持新增、编辑、启停、删除和设置默认。第一条问题自动成为默认；停用或删除默认问题后不自动改选。
- 问答发起只接收 `targetId`、模型列表和问题 ID。服务端重新解析目标、模型、凭据和问题快照，按“模型 × 问题”去重后顺序执行；每项独立 10 分钟 context，不发送 `max_tokens`，不重试。
- 发起阶段和后台执行均使用 `connection_health.Service` 生命周期，不受弹窗关闭或 HTTP 请求取消影响。同一用户和 `targetId` 的活动批次在服务内存及 PostgreSQL 事务中双重拦截。
- 主动终止会取消当前请求，保留已完成记录，将未完成记录改为 `cancelled`，等待工作协程和活动占用释放后再返回；服务 Shutdown 会取消并等待全部问答任务。启动时遗留的 `pending/running` 统一记为 `failed/service_restarted`。
- 保存内容只有归属、模型、问题快照、回答正文、状态、安全错误类型、人工错误标记和必要时间字段。上游错误 JSON、错误页、响应头、Usage、凭据和原始响应片段未进入记录。
- 设置页已增加“测试问题”标签；闪电弹窗保留原尺寸和滚动区，增加第三个“问答测试”模式，支持多选组合数、当前进度、2 秒轮询、最终刷新、主动终止、20 条分页历史和人工标错自动保存/失败回滚。

### 提交前复核修复

- 关闭、切换模式或更换目标时会立即释放问答发起中和终止中状态，并通过独立操作代次拒绝旧请求的迟到响应；快速关闭后重新打开不会锁死开始按钮。
- 模型发现和正式/一次性测试使用不同的前端 `AbortController`，启动正式探活不再取消正在进行的模型发现，不会污染一次性测试和问答模式的加载状态。
- 问答批次创建成功后先安排轮询，再刷新非关键历史区；紧随的历史请求失败不再中断进度和最终结果刷新。
- 后端批次已执行记录按 `started_at` 和 `completed_at` 返回，不依赖随机 UUID 排序；未新增组合序号或其他保存字段。前端最终不再单独抽取“最新回答”，避免同一记录重复展示。
- 终止请求绑定发起时的 `targetId`、`batchId` 和弹窗代次，并纳入关闭/切换时的前端取消；账号 A 的迟到响应不会覆盖账号 B 的状态。

### 状态展示与统计修复

- 人工标错和请求失败统一使用清晰的红色背景、边框和叉号；正常成功记录使用绿色背景、边框和更大的勾号。勾叉表达当前状态，人工标错按钮不再用“下一步操作”反向表达状态。
- 当前批次内 `pending` 和 `running` 记录都显示旋转状态，不再只有第一条运行记录转圈；成功、失败和终止分别显示勾、叉和中性终止图标。
- 每条已开始记录显示从 `startedAt` 到 `completedAt` 的回答耗时；仍在执行时由弹窗内单一秒级计时器更新，完成、关闭、切换模式或组件卸载后立即清理计时器。
- 问答模式顶部两行说明已移除。统计保留克制的“累计”和“今日（东八区）”两块，正常数和错误数作为主要数字，总数只在标题旁以“共 N 次”小字记录；两项主要数字使用同一套颜色和字号。今日统计按记录完成时间的 `Asia/Shanghai` 日历日期计算。

### 未查看提醒

- 问答批次成功创建后，以稳定 `targetId` 在当前 workspace 的既有本地显示偏好中记录“未查看”状态；页面刷新或同一账号出现在其他分组时仍使用同一份提醒，不新增服务端字段或接口。
- 账号行的闪电入口在存在未查看问答时显示为琥珀色实心状态。重新打开该账号弹窗后，只有进入“问答测试”标签才清除提醒；仅打开正式探活或一次性测试不会误清除。
- 该提醒只改变前端入口颜色和悬浮提示，不修改问答记录、健康状态、Priority、`schedulable`、探活任务或后台批次生命周期。

### 当前批次卡片重组

- 原“当前批次和最新回答”会把同一回答先完整展示、再在批次列表重复展示，最终改为单一“当前批次”区域，每个“模型 × 问题”只显示一次。
- 当前批次使用响应式结果卡片：一项占整行，两项在中等宽度下左右排列，三项及以上在宽屏下最多三列并自动换行；窄屏统一单列，不改变弹窗尺寸和内部滚动方式。
- 每张卡片直接展示问题名称、模型、状态、回答耗时、问题正文和回答正文；等待、执行、失败和终止也显示对应内容。问题与回答默认保留可读摘要，并提供“展开详情 / 收起详情”查看完整快照。
