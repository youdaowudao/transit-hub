# 20260811 未完成任务：分组健康调度清单读取优化

状态：未完成，当前不实施

## 当前结论

`AdminProbeTarget` 属于早期既有设计。调度 job 在 target lease 后再次完整读取分组、账号、成员关系和策略，是后续为执行前新鲜度加入的保护。

当前决定保留这次执行前刷新。`V2.1.14` 的最后 active 保底只能复用该刷新结果，不得为了减少请求删除它，也不得增加第三次清单读取或写后 readback。

原因：初始 inventory 与实际执行之间可能经历排队；人工或其他系统也可能在此期间改变主站账号状态或分组成员。直接改为单轮单清单会扩大陈旧信息窗口，并可能使本地按旧 active 数量关闭最后账号。

## 后续研究前提

- 先记录当前每个 workspace、每个 target 的实际主站请求量、调度时长、失败率和排队时间，不能凭感觉删刷新。
- 先确认 Sub2API 是否存在能够一次返回账号当前状态、完整成员关系和版本/变更标识的低成本接口；没有可靠权威来源时不实施压缩读取。
- 必须用并发 job、长队列、人工主站修改、成员变更和写入结果不明确场景证明：新方案不会把最后 active 关掉，也不会让 suspended 目标停止后续探活。
- 读取优化必须作为独立变更，先重写 SPEC、PLAN 和验证方案；不得混入分组保底、Priority、状态机或新的 safety gate 工作。
